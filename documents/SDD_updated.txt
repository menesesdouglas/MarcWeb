Este documento define o design do **Marc Web**, com **MVP funcional 95% completo** em arquitetura single-tenant, totalmente preparado para evolução multi-tenant com **Spring Cloud (Eureka + Gateway)**.

## **5. Arquitetura Multi-tenant com Eureka (Sprints 13-16)**

### **5.1 Biblioteca Compartilhada (empresa-common-lib)**

#### **Estrutura:**

```java
// DTOs compartilhados
package com.marcweb.common.dto;

public record LoginRequest(String username, String password) {}
public record LoginResponse(
    String token,
    String tokenType,
    Long userId,
    String username,
    String role
) {}

// Interfaces de serviços
package com.marcweb.common.service;

public interface UserService {
    void createUser(CreateUser data);
    User findByUsername(String username);
    void editUser(Long id, CreateUser data);
    void deleteUser(Long id);
}

public interface RegistroPontoService {
    void registrarPonto(CreateRegistroPonto data, HttpServletRequest request);
    List<RegistroPontoResponse> buscarPontos(LocalDateTime start, LocalDateTime end);
}
```

## **6. Benefícios da Arquitetura Proposta**

| Benefício | Como Acontece |
|-----------|---------------|
| **Reutilização de código** | Via `empresa-common-lib` |
| **Isolamento de dados** | Cada serviço com seu banco |
| **Comunicação dinâmica** | Eureka + Feign/WebClient |
| **Escalabilidade** | Cada serviço escala independentemente |
| **Manutenção** | Alterações na lib refletem em todos |
| **Deploy flexível** | Empresas podem ter versões diferentes |
| **Desenvolvimento focado** | MVP primeiro, multi-tenant depois |
| **Interface completa** | Frontend funcional e integrado |
| **Experiência de usuário** | Interface amigável e responsiva |
