## 🔐 AUTENTICAÇÃO

### 1.1 Login Admin Padrão
**Endpoint:** `POST http://localhost:8080/api/auth/login`  
**Headers:** `Content-Type: application/json`

```json
{
  "username": "admin",
  "password": "admin123"
}
```

**Resposta Esperada (200 OK):**
```json
{
  "token": "eyJhbGciOiJIUzI1NiJ9...",
  "tokenType": "Bearer",
  "userId": 1,
  "username": "admin",
  "role": "ADMIN"
}
```

**Ação:** Copie o token da resposta e use nos próximos requests como:  
`Authorization: Bearer {TOKEN_AQUI}`

## 🛠️ FERRAMENTAS RECOMENDADAS

### Postman
1. Importar coleção com todos os requests acima
2. Criar environment variables:
   - `base_url`: http://localhost:8080
   - `admin_token`: (copiar após login)
   - `employee_token`: (copiar após login)

### cURL (Terminal)
```bash
# Login
curl -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin123"}'

# Registrar ponto (substitua TOKEN)
curl -X POST http://localhost:8080/api/ponto \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer TOKEN" \
  -d '{"tipo":"ENTRADA"}'
```

### HTTPie (Alternativa mais simples)
```bash
# Login
http POST localhost:8080/api/auth/login username=admin password=admin123

# Registrar ponto
http POST localhost:8080/api/ponto Authorization:"Bearer TOKEN" tipo=ENTRADA
```

## 📝 NOTAS IMPORTANTES

1. **Timestamps:** O sistema usa @CreatedDate, então não é possível especificar timestamp customizado nos testes básicos
2. **IP:** Sistema captura automaticamente do header X-Forwarded-For ou RemoteAddr
3. **Validação de Geoloc:** Atualmente NÃO implementada (BUG-003)
4. **Múltiplos Ciclos:** Sistema permite mas deveria ter validação adicional
5. **Timezone:** Sistema usa LocalDateTime do servidor
