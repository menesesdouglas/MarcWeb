# **Software Design Document (SDD) Detalhado – Marc Web**  
**Sistema de Ponto Eletrônico Web Multi-tenant**  
**Versão 2.0 – Janeiro 2026**  
**(Atualizado: Nova Arquitetura Multi-empresa + Folha de Pagamento Completa)**

---

## **1. Introdução**

### **1.1 Propósito**
Este documento fornece o design completo e atualizado do **Marc Web**, uma migração web do sistema de ponto eletrônico offline **Marc** (original em Python). O sistema agora suporta **múltiplas empresas** com arquitetura multi-tenant, incluindo **cálculos completos de folha de pagamento** conforme legislação trabalhista brasileira (CLT, INSS, FGTS).

### **1.2 Escopo**

#### **Funcionalidades Core (Prioridade Alta):**
- ✅ Registro de ponto (entrada/saída/descansos)
- ✅ Gestão de funcionários por empresa
- ✅ Calendário (feriados nacionais + folgas individuais + domingos automáticos)
- ✅ Folha de ponto detalhada (JSON estruturado)
- ✅ Sistema de logs unificado
- ✅ Relatórios mensais com cálculo de horas
- ✅ Exportação PDF
- ✅ Auditoria de ações
- ✅ Backups automáticos
- ✅ Arquitetura Multi-tenant

#### **Funcionalidades Secundárias (Implementação Futura):**
- 🔄 **Contracheque completo** - Funcionalidade em amadurecimento, não é foco principal
  - Será implementada após MVP estável
  - Requer análise aprofundada de legislação trabalhista
  - Desenvolvimento nas últimas sprints

#### **Arquitetura Multi-tenant:**
- **Banco de dados por empresa** (isolamento completo)
- **Banco de dados principal** (gerenciamento de empresas)
- **Login centralizado** via portal principal
- **APIs independentes** por empresa (porta dedicada)
- Configurações independentes por empresa

#### **Removido:**
- ❌ Solicitação de folga usando banco de horas

### **1.3 Restrições e Requisitos Iniciais**
- **Hardware:** Notebook Dell Latitude E6400 (Linux Mint, 4GB RAM) e PC Windows 10 (4GB RAM)
- **Tempo:** 2h/dia; estimativa total 8-12 meses (reduzível com IA)
- **Conformidade:** CLT, LGPD, cálculos trabalhistas brasileiros
- **Escalabilidade:** Suportar até 100 empresas por servidor

## **2. Arquitetura do Sistema**

### **2.1 Visão Geral - Arquitetura Multi-tenant com Login Centralizado**

```
┌──────────────────────────────────────────────────────────────────────┐
│                   marcweb.com.br (Portal Principal)                  │
│         Frontend: Tela de Login + Seleção de Empresa                │
└────────────┬─────────────────────────────────────────────────────────┘
             │
             ├─> Consulta Lista de Empresas ──> PostgreSQL: marcweb_main
             │                                   (nome, url_api, porta, ativo)
             │
             ├─> Login Request ──> API Empresa A (http://empresa-a.api:8081)
             │                     PostgreSQL: marcweb_empresa_a
             │
             ├─> Login Request ──> API Empresa B (http://empresa-b.api:8082)
             │                     PostgreSQL: marcweb_empresa_b
             │
             └─> Login Request ──> API Empresa N (http://empresa-n.api:808N)
                                   PostgreSQL: marcweb_empresa_n

Fluxo de Autenticação:
1. User acessa marcweb.com.br
2. Seleciona empresa no dropdown
3. Digita credenciais
4. Frontend envia login para API específica (porta da empresa)
5. Se sucesso → Redireciona para domínio da empresa (empresa-a.marcweb.com.br)
6. Ao deslogar → Retorna para marcweb.com.br
```

**Validação no Backend:**
```java
@RestController
@RequestMapping("/api/public/empresas")
public class EmpresasPublicController {
    
    @GetMapping("/ativas")
    public ResponseEntity<List<EmpresaPublicDTO>> listarEmpresasAtivas() {
        // Retorna apenas empresas ativas
        // Não expõe dados sensíveis (porta, database_name, etc)
        List<EmpresaPublicDTO> empresas = empresaService.listarPublicas();
        
        // Log de acesso
        logSistemaService.registrar(
            null, // sem empresa específica
            "LISTAR_EMPRESAS",
            CategoriaLog.LOGIN,
            request.getRemoteAddr()
        );
        
        return ResponseEntity.ok(empresas);
    }
    
    @GetMapping("/{id}/api-config")
    public ResponseEntity<ApiConfigDTO> obterConfigApi(@PathVariable Long id) {
        Empresa empresa = empresaService.findById(id);
        
        if (!empresa.getAtiva()) {
            throw new EmpresaInativaException();
        }
        
        // Retorna apenas URL e porta (não expõe credenciais)
        return ResponseEntity.ok(new ApiConfigDTO(
            empresa.getUrlApi(),
            empresa.getPortaApi(),
            empresa.getSubdomain()
        ));
    }
}
```

**Rate Limiting:**
- Endpoint de listar empresas: 60 requisições/minuto por IP
- Endpoint de login (nas APIs das empresas): 5 tentativas/minuto por IP
- Após 5 falhas consecutivas: bloqueio temporário de 15 minutos

### **4.2 Gerenciamento Multi-tenant**

#### **Endpoints do Sistema Principal:**
- `POST /api/admin/empresas/criar` - Criar nova empresa (cria banco, usuário admin)
- `GET /api/admin/empresas` - Listar todas as empresas
- `PUT /api/admin/empresas/{id}` - Editar empresa
- `DELETE /api/admin/empresas/{id}` - Desativar empresa
- `POST /api/admin/empresas/{id}/backup` - Backup de empresa específica
- `GET /api/admin/logs/sistema` - Logs do sistema central

#### **Processo de Criação de Empresa:**
1. Admin cria empresa no banco principal
2. Sistema cria automaticamente:
   - Banco de dados PostgreSQL: `marcweb_empresa_{id}`
   - Executa migrations do Flyway
   - Cria usuário admin padrão da empresa
   - Configura porta da aplicação (8081, 8082...)
   - Atualiza configuração do NGINX
3. Empresa fica disponível em: `empresa1.marcweb.com.br`

### **4.2 Folgas Automáticas (NOVO)**

#### **Regra de Negócio:**
- **Todo domingo** é automaticamente marcado como folga
- Sistema **não permite** registro de ponto aos domingos (exceto com permissão especial)
- Folha de ponto marca domingos como `tipo_dia: "DOMINGO"`
- Não desconta horas nem gera débito

#### **Implementação:**
```java
// Em RegistroPontoService
private void validarDiaUtil(LocalDateTime timestamp) {
    DayOfWeek diaSemana = timestamp.getDayOfWeek();
    if (diaSemana == DayOfWeek.SUNDAY) {
        throw new RegistroEmDomingoException("Não é permitido registrar ponto aos domingos");
    }
    
    // Verifica se é feriado
    LocalDate data = timestamp.toLocalDate();
    if (feriadoRepository.existsByData(data)) {
        throw new RegistroEmFeriadoException("Não é permitido registrar ponto em feriados");
    }
}
```

### **4.3 Folha de Ponto Detalhada**

#### **Endpoint:**
- `GET /api/folha-ponto/gerar?mes=1&ano=2026&userId=1` (admin)
- `GET /api/folha-ponto/me?mes=1&ano=2026` (funcionário)

#### **Processo:**
1. Busca todos os registros do mês/ano
2. Agrupa por dia
3. Calcula horas trabalhadas por dia
4. Identifica feriados, folgas, domingos
5. Calcula totalizações
6. Retorna JSON estruturado conforme modelo acima
7. Persiste na tabela `folhas_ponto`

### **4.4 Relatórios e Exportação PDF**

#### **Endpoints:**
- `GET /api/relatorios/mensal?userId=1&mes=1&ano=2026` (JSON)
- `GET /api/relatorios/mensal/pdf?userId=1&mes=1&ano=2026` (PDF)
- `GET /api/relatorios/periodo?userId=1&inicio=2026-01-01&fim=2026-12-31`

#### **Conteúdo do Relatório:**
- Cabeçalho com dados da empresa e funcionário
- Listagem de registros diários
- Cálculo de horas trabalhadas, extras e débitos
- Identificação de feriados e folgas
- Totalizações do período
- Assinatura digital (opcional)

        document.add(new Paragraph("Horas Trabalhadas: " + folha.getHorasTrabalhadas()));
        document.add(new Paragraph("Horas Extras: " + folha.getHorasExtras()));
        
        document.close();
        return baos.toByteArray();
    }
}

@Aspect
@Component
public class LogAuditoriaAspect {
    
    @Around("@annotation(Auditado)")
    public Object registrarLog(ProceedingJoinPoint joinPoint) throws Throwable {
        String acao = joinPoint.getSignature().getName();
        Object[] args = joinPoint.getArgs();
        UserDetails user = UserService.getUserDetailsBySecurityContext();
        
        try {
            Object result = joinPoint.proceed();
            logAuditoriaService.registrar(
                user, acao, CategoriaLog.AUDITORIA, "Sucesso", args
            );
            return result;
        } catch (Exception e) {
            logAuditoriaService.registrar(
                user, acao, CategoriaLog.AUDITORIA, "Erro: " + e.getMessage(), args
            );
            throw e;
        }
    }
}

server {
    listen 443 ssl;

    # Busca porta da empresa no banco (via script Lua ou fallback)

    location / {
        # Proxy para porta específica da empresa

**Script de Deploy de Nova Empresa:**
```bash
#!/bin/bash
# deploy-nova-empresa.sh

EMPRESA_SLUG=$1
PORTA=$2
DATABASE_NAME=$3

echo "Criando estrutura para empresa: $EMPRESA_SLUG"

# 1. Criar diretório
mkdir -p /opt/marcweb/empresas/$EMPRESA_SLUG

# 2. Copiar JAR
cp /opt/marcweb/templates/marcweb-app.jar /opt/marcweb/empresas/$EMPRESA_SLUG/

# 3. Criar configuração
cat > /opt/marcweb/empresas/$EMPRESA_SLUG/application-$EMPRESA_SLUG.yml <<EOF
server:
  port: $PORTA
spring:
  datasource:
    url: jdbc:postgresql://localhost:5432/$DATABASE_NAME
    username: marcuser
    password: \${DB_PASSWORD}
  jpa:
    hibernate:
      ddl-auto: validate
  flyway:
    enabled: true
    locations: classpath:db/migration
    baseline-on-migrate: true
EOF

# 4. Criar banco de dados
sudo -u postgres psql -c "CREATE DATABASE $DATABASE_NAME;"

# 5. Executar migrations
cd /opt/marcweb/empresas/$EMPRESA_SLUG
java -jar marcweb-app.jar --spring.profiles.active=$EMPRESA_SLUG --flyway.migrate

# 6. Criar service systemd
cat > /etc/systemd/system/marcweb-$EMPRESA_SLUG.service <<EOF
[Unit]
Description=Marc Web - $EMPRESA_SLUG
After=network.target

[Service]
Type=simple
User=marcweb
WorkingDirectory=/opt/marcweb/empresas/$EMPRESA_SLUG
ExecStart=/usr/bin/java -jar marcweb-app.jar --spring.profiles.active=$EMPRESA_SLUG
Restart=always
Environment="SERVER_PORT=$PORTA"

[Install]
WantedBy=multi-user.target
EOF

# 7. Habilitar e iniciar service
systemctl daemon-reload
systemctl enable marcweb-$EMPRESA_SLUG
systemctl start marcweb-$EMPRESA_SLUG

echo "Empresa $EMPRESA_SLUG deployada com sucesso!"
echo "API disponível em: http://localhost:$PORTA"
```

**Backup Automatizado:**
```bash
#!/bin/bash
# backup-empresas.sh

BACKUP_DIR=/var/backups/marcweb
DATE=$(date +%Y%m%d_%H%M%S)

# Backup do banco principal
pg_dump marcweb_main | gzip > $BACKUP_DIR/main_$DATE.sql.gz

# Backup de cada empresa
for db in $(psql -U postgres -t -c "SELECT database_name FROM marcweb_main.empresas WHERE ativa = true"); do
    pg_dump $db | gzip > $BACKUP_DIR/${db}_$DATE.sql.gz
done

# Limpar backups antigos (manter últimos 30 dias)
find $BACKUP_DIR -name "*.sql.gz" -mtime +30 -delete
```
