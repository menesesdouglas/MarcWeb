### **Sprint 6: Calendário e Controle de Ausências**
**Objetivo:** Gerenciar feriados e folgas individuais.

**Tarefas:**
- Completar FeriadoService (sincronização BrasilAPI + persistência)
- Criar endpoint `POST /api/feriados/sync`
- Criar FolgaService com CRUD completo
- Implementar validação de tipos de folga (FERIAS, ATESTADO, FALTA_JUSTIFICADA)
- **Lógica de folgas automáticas aos domingos**
- Controllers REST `/api/feriados` e `/api/folgas`
- Validar sobreposição de folgas
- Criar migration para persistir feriados

**Marco:** Feriados sincronizados e persistidos, folgas gerenciáveis, domingos automaticamente marcados como folga.

---

### **Sprint 7: Folha de Ponto Detalhada** ⭐
**Objetivo:** Implementar geração de folha de ponto em JSON estruturado.

**Tarefas:**
- Criar entidade `FolhaPonto` com campo JSONB
- Criar migration V2__add_folhas_ponto
- Criar FolhaPontoService:
  - Método `gerarFolhaPonto(userId, mes, ano)`
  - Agrupar registros por dia
  - Calcular horas trabalhadas, extras e débitos por dia
  - Identificar tipo de dia (UTIL, DOMINGO, FERIADO, FOLGA)
  - Gerar JSON conforme estrutura do SDD
- Criar endpoint `GET /api/folha-ponto/gerar?mes=X&ano=Y`
- Criar endpoint `GET /api/folha-ponto/me?mes=X&ano=Y` (funcionário)
- Persistir folha de ponto gerada no banco
- Validações: não regenerar se já existe, permitir forçar atualização

**Marco:** Folha de ponto detalhada em JSON disponível via API, com todas as informações estruturadas.

---

### **Sprint 8: Sistema de Logs Unificado** ⭐
**Objetivo:** Implementar logging abrangente em todo o sistema.

**Tarefas:**
- Criar LogAuditoriaService centralizado
- Implementar Aspect (@Auditado) para logar ações automaticamente
- Adicionar logs em:
  - Login/Logout
  - Registro de ponto
  - Criação/edição/exclusão de usuários
  - Geração de relatórios
  - Alterações em configurações
  - Sincronização de feriados
- Criar endpoint `GET /api/auditoria/logs` (admin only)
- Implementar filtros (data, usuário, ação, status)
- Adicionar paginação nos logs
- Implementar limpeza automática de logs antigos (> 90 dias)

**Marco:** Sistema de auditoria completo, todas as ações críticas registradas e rastreáveis.

---

### **Sprint 9: Arquitetura Multi-tenant - Portal Principal** ⭐
**Objetivo:** Criar portal de login centralizado e API de gerenciamento de empresas.

**Tarefas:**
- Criar projeto separado: `marcweb-portal` (frontend + API principal)
- Criar banco `marcweb_main`
- Criar migrations para tabelas:
  - `empresas` (com campos url_api, porta_api, slug)
  - `empresas_config_visual` (logos, cores)
  - `logs_sistema`
- Criar entidades: Empresa, EmpresaConfigVisual, LogSistema
- Criar EmpresaService com métodos:
  - `listarEmpresasAtivas()` - para select do login
  - `obterConfigApi(empresaId)` - retorna URL e porta
  - `criarEmpresa()` - provisiona nova empresa
  - `editarEmpresa()`
  - `desativarEmpresa()`
- Criar controllers:
  - `EmpresasPublicController` (endpoints públicos)
  - `AdminEmpresaController` (gerenciamento)
- Implementar frontend do portal:
  - Tela de login com select de empresas
  - Buscar lista de empresas via API
  - Enviar login para API específica da empresa
  - Redirecionar após autenticação bem-sucedida
- Configurar CORS para permitir comunicação entre domínios
- Implementar rate limiting no portal
- Criar script de provisionamento de empresa

**Marco:** Portal centralizado funcional, capaz de listar empresas e rotear login para APIs específicas.

---

### **Sprint 10: Multi-tenant - Redirecionamento e Isolamento** ⭐
**Objetivo:** Implementar fluxo completo de autenticação multi-tenant e isolamento.

**Tarefas:**
- Adicionar campo `empresaId` no payload do JWT de cada empresa
- Modificar JwtService para incluir empresaId no token
- Criar filter de validação que verifica:
  - Token é válido
  - EmpresaId no token corresponde à empresa da API
  - Empresa está ativa
- Implementar RedirectService:
  - Determina URL de redirecionamento baseado em role
  - ADMIN → `/admin-panel.html`
  - EMPLOYEE → `/dashboard-funcionario.html`
  - Retorna URL completa com subdomínio
- Modificar endpoint de login para retornar:
  ```json
  {
    "token": "...",
    "redirectUrl": "https://empresa-x.marcweb.com.br/dashboard",
    "empresaSlug": "empresa-x"
  }
  ```
- Implementar logout universal:
  - Limpa token do localStorage
  - Redireciona para portal principal
  - Registra log de logout
- Configurar DNS para subdomínios (wildcard)
- Criar script de deploy por empresa
- Implementar systemd services por empresa
- Testes de isolamento:
  - Usuário da Empresa A não acessa dados da Empresa B
  - Token de uma empresa não funciona em outra
  - Validação de domínio/subdomínio
- Documentar fluxo completo de autenticação

**Marco:** Sistema multi-tenant completo, com login centralizado, redirecionamento automático e isolamento total de dados.

- Adicionar cabeçalho com logo e dados da empresa
- Implementar tabelas formatadas com dados de registro
- Adicionar totalizações e cálculos
- Implementar assinatura digital (opcional)
- Permitir download direto do PDF
- Validar permissões (funcionário só vê próprios relatórios)

**Marco:** Relatórios PDF profissionais disponíveis para download.
